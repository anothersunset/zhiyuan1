# Agent 自进化完善过程（Self-Evolution Loop）

> 让"语义感知 + 工具调用"的质量随真实使用持续提升的闭环流程。
> 灵感对标：Claude Code / ZCode 的上下文工程与回归纪律。

## 一、闭环结构

```text
        ┌────────────────────────────────────────────────┐
        │  ① 语料采集：线上误判 / 真实用户说法 / 探针预测     │
        └───────────────────┬────────────────────────────┘
                            ▼
        ② 线上执行器：script/agent-corpus/run_corpus.sh
           （注册临时账号 → 逐条独立会话 → 断言路由 → 打表）
        ────────────┬────────────────────────────
                    ▼
        ③ gap 分类处置
           ├─ 正则覆盖缺口 → AgentDecisionService 补同义词/分支
           ├─ 工具数据/结果缺陷 → Facade/Formatter 修复
           └─ 语义模糊（正则不适合处理）→ 标记 LLM 兜底层覆盖
        ────────────┬────────────────────────────
                    ▼
        ④ 固化：修复的语料补入 AgentIntentRegressionTest
           + run_corpus.sh 的 corpus.json，回归全绿
        ────────────┬────────────────────────────
                    ▼
        ⑤ 本地提交（不推 main，等用户确认）→ 重建 zhiyuan6 验证
        └──────────────► 回到 ①
```

## 二、组成部分

| 组成 | 位置 | 说明 |
|------|------|------|
| 意图回归语料 | `src/test/.../AgentIntentRegressionTest.java` | 32+ 条已固化语料，修改意图层前必须全绿 |
| 工具契约 | `src/test/.../AgentToolContractTest.java` | 10 工具参数校验/消息稳定性 |
| 上下文装配契约 | `src/test/.../AgentContextEngineeringTest.java` | 载荷出带/两级压缩/截断 |
| 线上执行器 | `script/agent-corpus/run_corpus.sh` + `corpus.json` | 对活栈跑语料清单（38 条），产 markdown 报告 |
| 意图层实现 | `AgentDecisionService`（正则快路径 + LLM 兜底 + 续槽 + 快照） | 修改前先跑语料，改完语料全绿 |

## 三、执行节奏

- **每次线上误判**（用户实测 / 本审计探针）：补语料 → 定位 → 修复 → 双层回归（单测 + 线上执行器）→ 本地提交。
- **每次意图层/工具层代码改动**：`./mvnw -o test` 全绿 → 重建 zhiyuan6 → `run_corpus.sh http://127.0.0.1:18080` 线上复测。
- **推送 main**：累积改动经用户本地验证并明确确认后，一次性推送（不得自行推送）。

## 四、语料分类口径

| 类别 | 判定 | 处置 |
|------|------|------|
| 正则可覆盖 | 有明确动词/名词锚点 | 补同义词/分支 |
| 语义模糊 | 指代、省略、口语化 | 标记 LLM 兜底层覆盖（配 Key 后生效） |
| 工具能力缺口 | 路由正确但工具做不到 | 评估加工具/参数，走规格层声明 |
| 产品语义决策 | 如"专科是否排除" | 报告给团队决策，不擅自改 |

## 五、已知边界（诚实清单）

- LLM Key 失效期间，语义模糊类语料会按 REPLY 兜底——这不是回归失败，是已知的降级路径；
- "把浙江大学加入志愿单"这类按名加入：路由正确但目标序号取最近推荐第 1 项（已知限制，规格声明里标注）；
- 一分一段/推荐轮数据的省份覆盖以当前数据导入为准（湖南 2024-2026）。
